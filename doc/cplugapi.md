# cplugapi — `/cplugapi/v1/*` reference

Fork-only HTTP surface that the desktop ControlPlugin client talks to. Runs
alongside upstream Forge Neo's `/sdapi/v1/*`, never modifies it.

- **Prefix:** `/cplugapi/v1`
- **Source:** `modules/cplugapi/` (single mount point in `modules/api/api.py`)
- **OpenAPI spec:** generated by `scripts/export_cplugapi_openapi.py` →
  `cplugapi-openapi.json` (gitignored). Schemas are codegen-ready for the
  Rust client.

## Enabling

cplugapi mounts automatically when Forge's API surface is enabled. The
fork's `webui-user.bat` already passes `--api`, so a default boot exposes
the surface on the same port as `/sdapi/v1/*`. No separate flag.

```text
http://127.0.0.1:7860/cplugapi/v1/identify    -> always reachable
http://127.0.0.1:7860/cplugapi/v1/health      -> auth-gated when --api-auth set
```

## Authentication

`/cplugapi/v1/*` inherits the same Basic-auth dependency as `/sdapi/v1/*`.
If you launch with `--api-auth user:pass`, every cplugapi route except
`/identify` requires those credentials. `/identify` is the only
unauthenticated endpoint on purpose: the client must be able to fingerprint
a backend before deciding whether to send credentials. WebSocket upgrades
under this prefix honour the same auth.

There is no second auth layer — no API keys, no JWT. Loopback bind +
`--api-auth` + the security middleware (below) is the security posture.

## Security middleware

Three browser-adjacent threats unique to "desktop client → loopback HTTP
server" are mitigated by middleware scoped to `/cplugapi/v1/*`. Outside
the prefix the middleware is a no-op so the byte-identity invariant on
`/sdapi/v1/*` is preserved.

| Threat | Mitigation | Tunable |
|---|---|---|
| CSRF / cross-origin abuse | Reject hostile `Origin` and `Sec-Fetch-Site` | `CPLUG_ALLOWED_ORIGINS` (csv) |
| DNS rebinding | Strict `Host` allow-list (loopback only by default) | `CPLUG_ALLOWED_HOSTS` (csv) |
| Body-size DoS | 32 MiB `Content-Length` cap | `CPLUG_MAX_BODY_BYTES` (int) |

Native clients (no `Origin` header) and `file://` pages (`Origin: null`)
are accepted; loopback browsers are accepted by regex match.

## Access log

One structured line per `/cplugapi/v1/*` request is emitted to the
`cplugapi.access` Python logger at INFO level. Format:

```text
GET /cplugapi/v1/health status=200 dur_ms=2.345 in=-1 out=145 req_id=req_abc
```

Fields (also exposed via the `LogRecord.extra` dict for JSON
formatters):

| Field | Meaning |
|---|---|
| `method` / `path` / `status` | HTTP verb, route, status code |
| `dur_ms` | Wall-clock spent server-side (everything inside our middleware chain — security + auth + handler). What the client measures minus this is network or client-side. |
| `in` / `out` | Request and response `Content-Length`, or `-1` if not declared |
| `req_id` | Same value as the `X-Request-Id` header — joins to client logs |
| `replayed=1` | Idempotency cache replay, not a real handler execution |
| `error=<ExceptionName>` | Handler raised before producing a response |

The middleware sits outermost in the chain by design — its `dur_ms`
spans every other cplugapi middleware plus the handler. Outside the
prefix it is a straight pass-through (zero log lines, zero overhead).

Set `CPLUG_ACCESS_LOG=0` (or `false`/`no`/`off`) to disable emission;
the middleware still installs but skips the format step. Capability
string: `request-log`.

## Cross-cutting headers

| Header | Direction | Purpose |
|---|---|---|
| `X-Request-Id` | both | Echoes client id or stamps `req_<token>`; correlates logs across the WebUI / native boundary. Stashed at `request.state.request_id`. |
| `Idempotency-Key` | inbound | On mutating methods (POST/PUT/PATCH/DELETE), retries with the same key replay the cached first response. 8–128 chars from the UUID/ULID/base64url alphabet. |
| `Idempotency-Replayed: true` | outbound | Marker on replayed responses. |

Idempotency cache: in-memory LRU, sized via `CPLUG_IDEMPOTENCY_MAX`
(default 1024) and `CPLUG_IDEMPOTENCY_TTL_S` (default 86400 s).

## Endpoints

All routes return JSON. Successful responses are 200 unless noted.

### `GET /identify` — public

Cheapest probe. Returns fork name / version / commit so a client can
distinguish this fork from upstream Forge Neo / vanilla A1111 without
sending credentials.

```json
{
  "fork": "controlplugin_webui",
  "fork_version": "0.1.0",
  "fork_commit": "...",
  "upstream": "forge-neo",
  "upstream_commit": "..."
}
```

Capability: `identify`.

### `GET /health` — liveness + capability advertisement

```json
{
  "status": "ok",            // or "busy" when queue_depth ≥ 3
  "capabilities": ["identify", "health", ...],
  "active_task_id": null,
  "queue_depth": 0
}
```

`?detailed=true` adds VRAM totals + forward-compat fields
(`warm_pool_slots`, `active_attention_backend`,
`comfy_finalization_tax_active`).

Capability: `health`.

### `GET /version` — verbose diagnostic dump

Fork + upstream identity, Python / platform / framework versions, torch
+ CUDA + GPU list, plus forward-compat placeholders. Cached for 60 s.

Capability: `version`.

### `POST /session/cancel/{id_task}` — per-task cancellation

Pops the task from the pending queue and (if it's the running task)
fires `shared.state.interrupt()`. Distinct from `/sdapi/v1/interrupt`,
which is global and cannot drain queued tasks.

```json
{ "id_task": "task(txt2img-XXXXXXX)", "state": "cancelled" }
```

State enum: `cancelled`, `already_cancelled`, `already_completed`,
`not_found`. Idempotent — re-posting a cancelled task returns
`already_cancelled`. Path param: 1–128 chars, regex
`^[A-Za-z0-9_:.\-()]+$`.

Capability: `session/cancel`.

### `POST /forge/preset/{name}` — atomic toggle bundle

Flips a coordinated set of `shared.opts` toggles that the live-sketching
client wants. Each preset returns `{toggle: previous_value}` so the
caller can audit what changed.

| Preset | Effect |
|---|---|
| `sketch` | TAESD live preview, every-5-step interval, ToMe ratio 0.3, CUDA warmup |
| `default` | Restore upstream defaults (RGB preview, every-step, ToMe 0.0) |

Unknown name → 404. Capability: `forge/preset`.

### `GET /livez` — k8s liveness

Unconditional 200. Tests the event loop only; never gated on model
state. Capability: `livez`.

### `GET /readyz` — k8s readiness

200 + `{"status": "ready", ...}` when torch is importable, a checkpoint
is loaded, and no fatal condition is recorded. 503 +
`{"status": "not_ready", "checks": {...}}` otherwise. Modules surface
fatal errors via `livez_readyz.record_last_error(kind, detail)` and
clear with `clear_last_error()`. Capability: `readyz`.

### `GET /queue` — task introspection

```json
{
  "running": [{"id_task": "...", "started_at": null}],
  "pending": [{"id_task": "...", "submitted_at": ..., "eta_ms_p50": null}],
  "history_recent": [{"id_task": "...", "finished_at": null}]
}
```

`eta_ms_p50` is a rolling 32-sample EMA of completion duration; `null`
until enough history accumulates. `history_recent` capped at 10 entries.
Capability: `queue`.

### `GET /models/active` — currently-loaded checkpoint

```json
{
  "loaded": true,
  "arch": "sdxl",
  "engine_class": "StableDiffusionXL",
  "checkpoint": "sd_xl_base_1.0.safetensors",
  "checkpoint_hash": "...",
  "checkpoint_sha256": "..."
}
```

`loaded=false` is a state, not an error — always returns 200.
`engine_class` is diagnostic-only; clients **must** gate on `arch`.
The `Flux` engine class covers both flux-dev and flux-schnell; this
endpoint returns the coarse `"flux"` label, refine via `/models/sd-checkpoints`.

Capability: `models/architecture`.

### `GET /models/sd-checkpoints` — disk-scan + arch tag

Strict superset of `/sdapi/v1/sd-models`: same fields plus per-file
`arch`, `dtype`, `error`, and a top-level `available_arches` summary.

```json
{
  "checkpoints": [
    {
      "title": "sd_xl_base_1.0 [..]",
      "model_name": "sd_xl_base_1.0",
      "filename": "sd_xl_base_1.0.safetensors",
      "hash": "...",
      "sha256": "...",
      "arch": "sdxl",
      "dtype": "F16",
      "error": null
    }
  ],
  "available_arches": ["flux", "sd15", "sdxl"]
}
```

Per-file resilience: a single corrupt or unparseable file yields
`error: {code, message}` on its own record without 500ing the listing.
Two-stage classification: safetensors header peek first (~ms), pickle
fallthrough for `.ckpt` / `.pt` / `.pth` / `.bin` (hundreds of ms,
amortised by LRU) via `torch.load(weights_only=True, map_location="meta")`
— same classifier sentinels run against both formats. Error codes
split by what the client should do with the file:

| Code | Meaning | `arch` label |
|---|---|---|
| `model_not_found` | File vanished between scan and peek | `unknown` |
| `permission_denied` | EACCES at open | `unknown` |
| `invalid_safetensors` | Safetensors header parse failed (truncated, corrupt, wrong format) | `unknown` |
| `pickle_parse_failed` | Tried `torch.load` but it failed (corrupt, `weights_only=True` refused a custom global, empty state-dict) | `unknown` |
| `gguf_unsupported` | `.gguf` binary tensor format — separate parser, not implemented | `unknown` |
| `unsupported_format` | `.safetensors.index.json` sharded manifest — not a single-file checkpoint | `not_a_checkpoint` |

`unknown` and `not_a_checkpoint` are both excluded from
`available_arches`, but they differ in client UX: `unknown` records
are real loadable models the client should still show; `not_a_checkpoint`
records should be hidden from mode pickers entirely.

Cache key is content-addressable `(abs_path, mtime_ns, size, st_ino)`
— file changes are picked up automatically. Cap via
`CPLUG_MODELS_CACHE_MAX` (default 4096).

Capability: `models/disk-scan`.

### `GET /models/architectures` — lightweight summary

Same compute as `/models/sd-checkpoints` but trims the response to just
`available_arches`. Drives the ControlPlugin mode picker without paying
the full listing's wire cost. Excludes `unknown` and `not_a_checkpoint`.

```json
{ "available_arches": ["flux", "sd15", "sdxl"] }
```

Capability: `models/architectures-available`.

## Architecture vocabulary

`arch` strings are lowercase identifiers from a fixed vocabulary (see
`modules/cplugapi/arch.py`). The classifier probes in "most specific
first" order: SAI Model Spec metadata fast-path → component filters
(LoRA / VAE-only / TE-only) → DiT sentinels (Flux > SD3 > PixArt >
Lumina-2 > Hunyuan-DiT) → UNet sentinels (SDXL refiner > SDXL > SD2 >
SD15) → Cascade → `unknown`.

Currently classified labels:
`sd15`, `sd2`, `sdxl`, `sdxl_refiner`, `sd3`, `flux`, `flux_schnell`,
`flux2`, `pixart_alpha`, `lumina2`, `hunyuan_dit`, `wan`, `mugen`,
`chroma`, `zimage`, `anima`, `ernie`, `qwen`, `unknown`,
`not_a_checkpoint`. (Some labels are reserved as engine-class targets
and don't yet have header sentinels — they're only returned by
`/models/active`.)

## Capability registry

`/health.capabilities[]` is the canonical list of features this build
wires. Strings are slash-only and lowercase (dot notation is treated as
a bug). Current set:

```text
identify
health
version
session/cancel
forge/preset
security/csrf-host-bodylimit
idempotency
livez
readyz
queue
models/architecture
models/disk-scan
models/architectures-available

```

## Hard invariants (CLAUDE.md)

1. `/sdapi/v1/*` is byte-identical to upstream Forge Neo. cplugapi never
   modifies, removes, or shadows a `/sdapi/v1/*` route.
2. All fork code lives in `modules/cplugapi/`. `modules/api/api.py` gets
   a single `app.include_router(...)` line.
3. Capability strings are slash-only, lowercase.
4. `/cplugapi/v1/*` (HTTP and WebSocket) inherits `--api-auth`; no
   second auth layer.
